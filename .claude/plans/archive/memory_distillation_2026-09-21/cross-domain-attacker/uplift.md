**Three clause extensions, in the rule's own `check:`/`tell:` form:**

- §1 PRECEDENT rider — **PRECEDENT-LAYER.** A two-layer precedent cited by one of
  its layer names inverts the conclusion instead of degrading it. check: map the
  new objects onto BOTH layers and keep the mapping that preserves field count and
  verb count. tell: a "thin data class" mapped onto the precedent's BINDER; in a
  data/binder split the data verbs return ARRAYS and only the binder returns
  OPERATORS, so an `import` direction refutes the mapping before any `isinstance`
  chain shows up. Founding case: CS4b, `FrameBase` (2 fields, zero math) cited as
  the rich class while `Basis` (6 verbs) was the actual analogue — read at the
  right layer the precedent argued FOR the design the proposal opposed.
- §1 NAME-FREE rider — **NAME-CARRIES-A-VERB.** check: grep the prose corpus for
  the proposed name AND the verb the object would own. tell: the wanted primitive
  already exists in MUTATING form on another type, or a charter has already ruled
  its REALIZATION and not just its name. Founding case: `Pencil.at(σ)` — the name
  was already the campaign's, the verb already shipped as a mutating solver method
  for depletion, and finding it was the strongest argument for the carve.
- §6c rider — **GATE-IS-SPELLABLE.** check: take every symbol on a chartered law's
  RHS and check it against the datum's method list, before understanding the math;
  for an `⟺`, check the two directions separately and ask what the shipped witness
  can distinguish. tell: a gate whose negative control the shipped witness passes
  (a true-but-vacuous `⟸` under an undeclared convention), or a law whose RHS names
  a morphism the datum does not have. Founding cases: CS4a
  (`bind(K)† = bind(K†) ⟺ tight` — the adjoint law is n&s for GALERKIN, tightness
  is n&s for MULTIPLICATIVITY, and the ℓ=0 witness satisfies both); CS4b (no kernel

## U2 — `process-discipline` "A refuted candidate is first-class output" gains the QUESTION

The rule (its own heading, and it names `cross-domain-attacker`'s UNEXPLORED block
in its `check:` list) requires the structural REASON. It does not say that a
refutation is relative to a QUESTION, and that gap actively destroys answers,
because a permanent "⛔ no lever" banner is what a later summariser carries
forward.

- Proposed clause — **REFUTED-FOR-WHICH-QUESTION.** Write "refuted FOR
  <question>; the FACT it establishes is <fact>". check: every ⛔ banner reused
  from a plan or a memory is checked against the question now being asked. tell: a
  bare "⛔ <frame> — no independent lever" carried across a change of question.
  Founding case: the symplectic / momentum-map frame — correctly refuted for a
  DESIGN question ("does it buy a better scheme?" — no, the chart that conserves
  `p` by construction IS MoC) and the decisive answer to a CLASSIFICATION question
  (a method using `p` as a coordinate generates no redistribution term; one using
  `(r,x)` must carry the connection), which a stale banner would have suppressed.
- The rule's `brief:` line currently carries only the `git checkout` sentence
  (L28). It would gain: *"a rejected candidate is reported with its one-line
  structural reason AND the question it was refuted for — the fact outlives the
  lever."*

## U3 — Fleet meta-lesson: MEASURE THE BRIEF'S PREMISE before arguing, gating or framing

This one is already sighted twice, in two different agents, and that is the
argument for the floor rather than for two identity files: `[M]`
`.claude/plans/memory_distillation_uplift_queue.md:100-102` holds
**`test-architect` A1 — new §0.7 "measure the premise before you gate it"** as an
AGENT.md promotion, and my M1 is the same lesson learned independently on design
briefs. A lesson two agents learned separately belongs in `.claude/rules/`, not in
two AGENT.mds.

- Proposed home: `process-discipline` (a new short section; alternative home
  `instrument-doctrine`, which owns HOW to count but not WHICH count a brief's
  framing presumes).
- Proposed clause — **MEASURE-THE-PREMISE.** A brief's framing is a claim about
  the tree, and the cheap measurement it presumes usually decides the answer.
  check: before arguing a proposal's scope, take the count it presumes — the
  runtime BRANCHES a proposed dispatcher would collapse; the FIBER of a proposed
  "problem → object" section; who CONSUMES the object a justification names (AST
  pass, `instrument-doctrine`); the attributes of the object where a proposed split
  is currently FUSED; the inversions a chartered discriminating rule produces on
  the tree's straddlers; whether a general-case derivation or an optimality theorem
  on the target space already settles the whole table. tell: N independent
  arguments for N rows of a table, or a proposal's scope debated before a single
  count is published.
- Rider — **REPORT-THE-COLLAPSE.** The measured answer is usually SMALLER than the
  proposal and somewhere else (a call site, a widened return type, a verb, a gate
  plus a refusal message, an oracle). Report the collapse plainly: it is good news
  for the requester, and the steelman usually survives at a smaller scale. tell: a
  deliverable sized to the proposal rather than to the finding.
- Founding cases: 4 construction sites / 0 branches / 4-member fiber refuted the
  iso-family factory; `SNSolver.__init__` sorted 12 Problem / 6 Strategy / 2
  Solution showed the carve ran through an object the brief never named; Pomraning
  1989 Eq. 68 replaced eight per-method arguments with one equation; Gauss
  optimality on `[-1,1]` bounded every possible μ-line reduction; `_orbit_closure`
  already computed the permutation and returned `bool`.

## U4 — `cross-domain-frames` Part C: Smell 17, now with a second shape

The queue holds **Smell 17 — a `-> bool` predicate whose BODY builds the object**
(`memory_distillation_uplift_queue.md:127-136`), held at ONE in-tree sighting. A
second sighting has since landed with the same CONSEQUENCE and a different CAUSE,
so the honest proposal is a two-shape smell rather than a re-submission of the
one-shape version:

> **Smell 17 — the primitive already exists and is not consumed.** Shape (a): a
> `is_*` / `check_*` / `*_closure` predicate whose body builds an index map,
> permutation, matching, partition or certificate and returns `bool` — the
> capability is not missing, its WITNESS is; fix by widening the return type, and
> the downstream re-implementations delete themselves. Shape (b): the predicate is
> complete, correct and TESTED, and wired only to the ADVISORY path
> (`select_*` / `recommend_*` / `default_*`) while the type it guards is
> constructible directly — sort the callers into advisory vs CONSTRUCTIVE; zero
> constructive callers means the gate is a suggestion and the fix is a call site,
> not machinery. Both shapes collapse a "build the machinery" proposal by an order
> of magnitude, which is the smell's payoff.

Distinct from Smell #16 shape 1 (that says "collapse two paths"; this says "one
path exists and its output is discarded or unconsumed"). Sightings: #326
`_orbit_closure` (shape a, two downstream re-implementations); #336
`AngularSymmetry.admits_domain` (shape b). Whether two shapes of one family clear
Part C's bar is the user's call, as it was for the one-shape version.
