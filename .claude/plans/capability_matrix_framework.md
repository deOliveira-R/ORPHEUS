## B. Architectural decision — meta-generator with auto-discovery (Option B4)

Trade-off table:

| Option | Pro | Con | Discoverability |
|---|---|---|---|
| B1: Stay in tools/, doc-only fix | Zero churn | Silo persists; FN regression already proves humans/AI miss it | ★ |
| B2: Move into orpheus/derivations/registry/ | Co-located | Build-tool ↔ runtime category error; Wave-3 reserves namespace for runtime | ★★ |
| B3: Pure auto-discovery via `__capability__` attribute | Future-proof | Retrofit cost; convention drift | ★★★ |
| **B4: Hybrid — `cases.py:capability_rows()` + meta-generator** | Builds on existing `continuous_cases()` pattern; zero retrofit | Slight indirection | ★★★ |

**B4 wins** because the peierls package already exposes `capability_rows()`. Pattern is set; missing piece is the meta-generator.

### Concrete design

**File**: `tools/verification/generate_capability_matrices.py` — single meta-generator.

**Discovery loop** (pseudocode):
```python
for pkg in pkgutil.iter_modules(orpheus.derivations.continuous):
    try:
        cases_mod = importlib.import_module(f"{pkg.name}.cases")
    except ImportError:
        continue
    fn = getattr(cases_mod, "capability_rows", None)
    if fn is None:
        continue
    rows = fn()
    out = docs/theory/_<pkg.name>_capability_matrix.inc.rst
    out.write_text(_render(pkg.name, rows))
```

**Schema contract** (codified in meta-generator docstring):
- Required: `name`, `geometry`, `n_groups`, `n_regions`, `bc`, `status`
- Optional (auto-detected per row presence): `r0_over_R`, `closure`, `accuracy`, `scattering_order`, `multiplying`, `topology_class`, `extra` (dict)

**Sphinx hook**: collapse two hooks into one `_regenerate_capability_matrices` running `python -m tools.verification.generate_capability_matrices`.

**Per-page inclusion**: each method's theory page carries its own `.. include:: _<pkg_name>_capability_matrix.inc.rst`.

**Cleanup**: meta-generator wipes `docs/theory/_*_capability_matrix.inc.rst` at start, rewrites discovered ones. Stale removed.

**Test gate**: `tests/derivations/test_capability_matrices.py` runs `--check` mode (nonzero exit if output would change). Replaces never-landed `test_peierls_capability_matrix.py`.

## C. Pattern for new methods (worked example: FN)

1. Create `orpheus/derivations/continuous/fn_method/cases.py`
2. Define `capability_rows() -> list[dict[str, object]]` (multi-group k_inf cases — PUa-1-0-IN, PU-2-0-IN; future slab/sphere F_N benchmarks)
3. Add `Capabilities at a glance` section to `docs/theory/fn_method.rst` with `.. include:: _fn_method_capability_matrix.inc.rst`
4. Run `python -m tools.verification.generate_capability_matrices` — matrix appears
5. `pytest tests/derivations/test_capability_matrices.py` passes

Estimated effort: ~45 min for FN (no `cases.py` exists); ~30 min per backfill method.

- Package's `cases.py` raises ImportError → meta-generator catches and emits Sphinx warning, not hard failure (mirrors existing `try/except` in conf.py hooks)
- External link rot from rename → archivist closeout note records old→new mapping
