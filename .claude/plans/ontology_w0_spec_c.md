### 1.5 Conventions that hold in every unit

1. A tracked module of `tools/concept_table/` imports only the standard library (`ast`, `tokenize`, `tomllib`, `hashlib`, `dataclasses`, `pathlib`, `re`, `io`, `collections`, `typing`, `sys`) and its siblings. It imports nothing from `orpheus` (D3) and nothing from `tests`. The order `FORBIDDEN_EDGES` is passed in as an argument (M3 of `measure_tooling.md`: a pass in a non-test module takes it as a parameter). Layer rule: `tools/` is outside the layer table, which scans `orpheus/` only [M: `tests/gates/test_layer_imports.py`, `ORPHEUS_ROOT`], so these files are bound by this rule alone.
2. A gate file lives in `tests/gates/` at the root of the directory, beside `test_layer_imports.py`, carries `pytestmark = pytest.mark.foundation`, and reads the tree it runs in by path (`Path(__file__).resolve().parents[2]`), never by import and never under `scratch/` (D3).
3. Every check function is pure and typed. It takes values (mappings of source text, the table, the forbidden-edge mapping) and returns the frozenset of its **violations**, each a value of the same type as the debt entry that pins it (2.2): `EdgeViolation` is `EdgeDebt`, `MisplacedViolation` is `ClassDebt`, and so on, so that no string is parsed and no second representation exists (elegance V1). No check takes the debt as an argument. One function, `pin(measured, pinned) -> (unpinned, stale)`, compares a measured set with a pinned set, and every gate that pins a list calls it once and nowhere else. A message is produced by the violation's `__str__` at the end, never earlier. A planted fixture and a mutation are then values edited in memory, never a file edited on disk and never `git checkout` (`process-discipline`, mutation testing), so a mutation battery is crash-safe by construction.
4. Docstrings state the law the function checks, whole, with its converse where it has one; every message names the class or concept at fault and the file that fixes it.
5. Closedness: every enumeration (roles, kinds, sub-kinds, the four phases of `PHASE_ORDER`, waves, edge kinds, debt lists) is a tuple constant in one module and a loader refuses a value outside it; the absence of a phase is not a member of `PHASE_ORDER` (2.2). The sum `Head` of 2.2 is closed (four arms, refused otherwise). The declaration grammar is closed (its field set and order are fixed).
6. Stage-2 note: no class here is a generator in the sense of the architecture rules; these are tools beside the production tree and do not enter the concept table (the population is `orpheus/`).

### 2.2 Types, fields, invariants (each with where it is refused)

All are frozen dataclasses unless stated. "Refused" names the site that raises. Two sites never refuse the same invariant (elegance C1): the loaders `load_table` and `load_debt` parse and raise on everything a single row can violate; the checks of 2.8 return violations only for facts that need two rows or the tree.

- `ClassKey(file: str, qualname: str)` (NamedTuple). `file` is the repository-relative path under `orpheus/`; `qualname` is `Name` for a module-level class and `outer.<locals>.Name` for a function-local one. `str(key)` is `file::qualname`, the spelling used in the debt file. **`ClassKey.dotted`** is the one definition of a class's dotted name: the file path without `.py` with `/` replaced by `.`, a package `__init__.py` collapsing to the package path, then `.` and the qualname (`orpheus/sn/loss_representation/__init__.py::LossRepresentation` is `orpheus.sn.loss_representation.LossRepresentation`; **one rule for a function-local class**: the `outer.<locals>.` prefix is dropped, so `orpheus/memo/_traced_memo_boot.py::_libproc_thread_counter.<locals>.TaskInfo` is `orpheus.memo._traced_memo_boot.TaskInfo`, the spelling of the kit's edge `<functions>` to `TaskInfo` (the one edge whose endpoint is a local class), and the port therefore maps 3006 of 3006 kit edges [M] `amend/pass2/p_misc.py`: 676 of 676 dotted names are distinct under this rule, and the population refuses two keys with one dotted name; the reference pass, the checks and the page of unit `concept-page` all call it and nothing else spells the rule). Invariant: unique per population, and unique in `dotted` (refused by `population.read_population`, which raises `DuplicateClass`).
- `Declaration(concept, role, kind, subkind, welded)`: defined in `declaration.py` (2.3). ### 2.3 The declaration grammar, whole, and the reader's behaviour on every header shape

Grammar (one spelling; exactly this field order; separator ` | `):

`# concept: <id> | role: <role> | kind: <kind>[.<subkind>] [| welded: <id>, <id>, ...]`

`role` is one of `head, arm, weld, part, component, interface, twin, annex`; `kind` one of `set, measure, space, element, morphism, record, apparatus`; `subkind` as in 2.2. There is no module-level default: each class names its own concept (D2). Text after a second `#` on the same line is a separate comment and ignored by the parser (`parse_declaration` takes the text between the first and second `#`). `render()` and `parse_declaration` are inverse on canonical text (the read-back of 2.5 is that law over 676 rows).

Placement (decided by M4 and M5): the declaration is a TRAILING comment on the physical line that ends the class header, the line holding the colon at bracket depth 0, so the compiled code and every line number of every production file are unchanged. The comment line above the class (placement b) is refused by the reader as an orphan marker.

Reader behaviour on each shape of M2, all exercised by the fixtures of 2.8:
1. Single-line header, no decorator: the marker sits at the end of that line.
2. Decorated class (393 of 676): `ast.ClassDef.lineno` is the `class` line, not the decorator line (Python 3.8 and later); the header span starts at `class`. A marker on a decorator line is an orphan (G1 red).
3. Header on several lines (8 of 676): the end is found by tokenizing from the `class` keyword and counting brackets to the first `:` at depth 0 (`header_end`); the marker sits on that line only. A marker on an earlier header line is an orphan.
4. A comment already on the header-end line (2 of 676): the writer inserts the declaration before it, keeping it after a second `#` (`class X(...):  # concept: ... | kind: record  # noqa: E501`); the reader returns the whole comment token and the parser stops at the second `#`.
5. A body on the header line (`class E(Exception): pass`, 0 of 676 today): the comment still trails the physical line; the writer refuses a line that ends inside a multi-line string token (`SystemExit`), which cannot occur today (0 of 676) and so is a guard with a named witness (planted fixture), not a handled case.
6. A function-local class (`TaskInfo`): found by the walk through function bodies, qualname `outer.<locals>.Name`.
7. Two markers on one header-end line cannot be tokenized (one comment token per line); two declarations on two lines of the same header are one marker plus one orphan.
8. A class nested in a class (0 of 676): qualname `Outer.Inner`; the walk handles it; nothing in the tree exercises it, so a planted fixture does.

The reader tokenizes and parses with `ast`; nothing is imported and nothing runs (D2).
