## Final shape (the load-bearing design)
- **Field split:** base = `{bulk, boundary}`; subclass ADDS `{_history, history_depth}`. `_history` element type is `FullField` (a historical frame is a timeless snapshot — built by `advance` via `FullField(bulk=self.bulk, boundary=self.boundary)`).
- **`_recombine` hook:** base `def _recombine(self: T, *, bulk, boundary) -> T: return replace(self, bulk=bulk, boundary=boundary)`. The `replace(self, ...)` spelling is **provably `T`** (no `# type: ignore`) AND correct for the base (FullField has no history to drop). `TimedFullField` OVERRIDES it to `return TimedFullField(bulk=..., boundary=..., _history=(), history_depth=self.history_depth)` — `replace` would COPY the history (wrong), so the override is necessary, not just cosmetic. The 6 dunders are defined ONCE on the base and route through `self._recombine(...)`.
- **Self-type idiom (the pyright hinge):** `T = TypeVar("T", bound="FullField")`; the 6 dunders + `_recombine` + `copy` are typed `(self: T, ...) -> T` — MIRRORS `numerics/field.py`'s `T = TypeVar("T", bound="Field")`. This is what makes `TimedFullField` satisfy the `Vector` `Self` contract: the inherited `TimedFullField.__add__` types as `(other: TimedFullField) -> TimedFullField`. WITHOUT it, `MultiplicationOperator(LinearOperatorMixin["TimedFullField"])` reddened (`TimedFullField` "incompatible with protocol Vector" because the inherited `__add__` returned `FullField` not `Self`) — the +14-error cascade.
- **`_check_partner` widened to `isinstance(other, FullField)`** (NOT `type(other) is type(self)`). Load-bearing for the time-derivative stencil `state.at_lag(0) - state.at_lag(1)`: the current frame is `TimedFullField`, a historical frame is a timeless `FullField` snapshot, and the two MUST subtract. The CONCRETE result type is governed by `_recombine` (timed − timeless → timed via the timed hook), so accepting the base partner does NOT weaken the empty-history guarantee. Kept the error message phrase `"requires a same-class partner"` EXACTLY (the `test_wrong_type_rejected` regex pins it; do not paraphrase).
- **`zeros`/`from_flat` split:** base `zeros(*, bulk, boundary, mesh)` (no history_depth); `TimedFullField.zeros` adds `history_depth=2` param. base `from_flat(flat, template: FullField) -> FullField`; `TimedFullField.from_flat(flat, template: TimedFullField) -> TimedFullField` reads `template.history_depth`.

## Bit-identity guarantees
- `TimedFullField + TimedFullField` (recombine path): the inherited base `__add__` runs `self.bulk + other.bulk` / `self.boundary + other.boundary` (IDENTICAL leaf arithmetic to the old direct-construct body) then routes through the overridden `_recombine` → `TimedFullField(..., _history=(), history_depth=self.history_depth)` (IDENTICAL to the old body's explicit `_history=(), history_depth=self.history_depth`). ## ⚠ THE ONE `# type: ignore` (justified, design-forced)
`TimedFullField.from_flat` carries `# type: ignore[override]` — narrowing the classmethod `template: FullField` → `TimedFullField` is a Liskov param-narrowing pyright flags (`reportIncompatibleMethodOverride`). FORCED: the body reads `template.history_depth` which the base lacks; widening to `FullField` would break the access. This is the SAME category as the original `zeros`' `# type: ignore[attr-defined]` (design-forced, not a workaround). I removed the unneeded `[override]` ignores on `_recombine` (now clean via self-type) and `zeros` (signature widening is variance-OK). Net: 1 design-forced `[override]` + the inherited `[attr-defined]` ×2 in `zeros` (carried over from the original). The `# type: ignore[return-value]` I first put in base `_recombine` was ELIMINATED by switching to `replace(self, ...)`.

## LESSON (coding-elegance + pyright)
A polymorphic "recombine to Self with empty-metadata" hook over a frozen-dataclass inheritance pair has THREE pyright traps, each with a clean (ignore-free) spelling: (1) the base body that constructs the concrete base is NOT provably `T` — spell it `replace(self, ...)` (provably `T`) NOT `BaseClass(...)` (needs a `# type: ignore[return-value]`), and let the subclass OVERRIDE only because `replace` would copy the metadata it must drop; (2) the 6 dunders + `copy` MUST be typed `(self: T) -> T` with `T = TypeVar(bound=Base)` (the `numerics/field.py` idiom) or the subclass fails the `Vector` `Self` protocol and every `LinearOperatorMixin["Subclass"]` site reddens — measure the operator-file delta directly, the +N cascade lands far from the carrier; (3) a classmethod override that NARROWS a param to read a subclass-only attr (`from_flat(template: Subclass)` reading `history_depth`) is a genuine Liskov narrowing → one design-forced `# type: ignore[override]`, NOT avoidable without a duck-typed `getattr`. Also: when extracting a base whose `_history` elements become the base type, audit the EXISTING consumer that subtracts `at_lag(k)` against the current subclass — widen `_check_partner` to `isinstance(other, Base)` (the result type stays correct via the recombine hook), but keep the legacy error-message phrase verbatim (a regex-pinned test catches a paraphrase). Baseline pyright comparison across a git worktree is ONLY valid with the main `.venv` symlinked into the worktree root (pyrightconfig `venv: .venv`); without it the worktree silently analyzes a different file set and reports a non-comparable count.
