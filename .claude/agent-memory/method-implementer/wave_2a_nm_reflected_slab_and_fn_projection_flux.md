### Extension 2 — Path A.i ↔ Path B flux cross-check

**Honest verdict — the structural-independence claim does NOT hold at the user's optimistic 1e-9 tolerance.**

| Case | n_quad=128 | n_quad=256 | Spec target |
|------|---|---|---|
| Ua-1-0-SL (c=1.30, a=0.94 mfp) | ~2e-2 max rel diff | ~1e-2 | 1e-9 |
| PUa-1-0-SL (c=1.50, a=0.61 mfp) | ~2e-2 | ~1e-2 | 1e-9 |
| PUb-1-0-SL (c=1.40) | ~3e-2 | ~1e-2 | 1e-9 |
| UD2O-1-0-SL (c=1.02, a=5.66 mfp — thick) | **~65%** | ~50% | 1e-9 — EXCLUDED |

**Why the 1e-9 spec was unrealistic**: The Peierls integral kernel `(c/2) E_1(|z-z'|)` carries an integrable logarithmic singularity at z = z' which limits plain Nyström-style quadrature to algebraic O(1/n) convergence. Going from 1e-2 to 1e-9 would require ~10^7 quadrature nodes — infeasible. The spec confused "structural independence" (achieved — different algorithm classes) with "numerical agreement at machine precision" (NOT achieved without singularity-aware quadrature).

**What was achieved**: The structural-independence claim AT THE ALGORITHM LEVEL. Path A.i (BTE phase-space iteration) and Path B (KLL Wiener-Hopf + Fredholm) use procedurally distinct algorithms, both recovering the same eigenmode at the achievable tolerance (~1-3% on flux ratios for thin/medium slabs at n_quad=128).

**Recommendation for tightening to 1e-9**: Implement Atkinson product-Nyström or Gauss-Jacobi quadrature for the singular Peierls kernel. Estimated effort: ~1 week. Out of scope for Wave 2-A (which was scoped at <1 day per memo).

2. Sood's "Reference 9" uses different Pu-239 (a) cross sections than the (c=1.50) value cited.
3. Genuine method disagreement between F_N (NM 1980) and Sood's "Reference 9" method (not yet identified — possibly P_N + invariance per Neshat-Siewert-Ishiguro 1977).

**Recommendation**: Skip the Sood `*-H2O(N)-1-0-SL` registry cases for now; trust NM Table 2 + Burkart "Exact" as the L1 anchor. If/when the user wants the full Sood reflected-slab parity, follow-up work should reconcile this discrepancy first (likely needs a literature pull on the Sood "Reference 9" Burkart 1975 PhD thesis or its journal version).

### Architectural finding: the (3N+3) homogeneous system has spurious zeros

I initially attempted a direct `det = 0` formulation on the full (3N+3)×(3N+3) homogeneous system (embedding ν_0 in the Eq. 12 collocation grid). This produced highly oscillatory `det(τ)` with many sign changes — most NOT corresponding to the physical critical mode.

The correct NM approach (which I converged on) is the iterative scheme: solve (3N+2)-system at fixed τ with a_0=1, then root-find Eq. 15. The (3N+2) system is well-conditioned at non-critical τ; Eq. 15 residual cleanly identifies the critical τ (smooth function with one sign change in the physical neighborhood).

**Lesson for `algebra-of-record` skill / `numerical-bug-signatures`**: Embedding a Case discrete-eigenvalue collocation row in an otherwise real-valued homogeneous system creates a degenerate solution structure where complex-conjugate eigenmodes contaminate the determinant root-find. The cleaner pattern is to keep the discrete-eigenvalue condition SEPARATE from the (real-valued) collocation system.

## Skill / catalog updates proposed

No new ERR-NNN catalog entries — this Wave caught no production-code bugs (only my own development-time bugs, which are not catalogued per `vv-principles` discipline).

Two skill updates proposed:

### `algebra-of-record` skill — add a "discrete-eigenvalue-aware system solving" anti-pattern

The architectural finding above (about embedding ν_0 collocation in a homogeneous system) is generalisable beyond F_N method. Add to `algebra-of-record/SKILL.md` § anti-patterns:

> **NEVER embed a complex/imaginary discrete-eigenvalue collocation row in an otherwise real-valued homogeneous F_N-style system** when relying on `det = 0` as the critical condition. The det function becomes highly oscillatory (multiple sign changes from complex-conjugate eigenmode contamination) and root-finding becomes unreliable. Instead, keep the discrete-eigenvalue condition SEPARATE: solve the real-valued (3N+2)-system at fixed parameter, then enforce the discrete-eigenvalue critical condition by 1D root-find on the residual. This is NM 1980's pattern, and avoids ~50% of the F_N-style spurious roots.

### `numerical-bug-signatures` — add Signature: Singular-kernel Nyström algebraic convergence trap

Add a new signature documenting the Path A.i discovery:

> **Signature N: Slow algebraic convergence from logarithmic-singular kernels under plain Nyström**
> - Symptom: A flux/eigenmode integral solver with structurally correct algorithm gives sub-1% accuracy at n=128 but cannot reach 1e-9 even at n=10^4. Convergence rate ~1/n, not exponential.
> - Mechanism: The integrand (e.g. Peierls kernel `E_1(|z-z'|)`) has an integrable logarithmic singularity at the diagonal that plain Gauss-Legendre / equally-spaced Nyström integrates with O(1/n) error per row. Cumulative error over the full operator is ~1/n.
> - Diagnostic probe: Convergence rate test — refine n by 2× and check error reduction. Plain Nyström gives factor ~2 reduction (algebraic O(1/n)); singularity-aware Nyström gives factor 4-100× (algebraic high-order or exponential).
> - Catching test: any cross-check vs an independently-verified reference at progressively finer grids; the slope of error-vs-1/n on log-log plot reveals the convergence order.
> - Lesson: For singular kernels, plain Gauss-Legendre is INSUFFICIENT for engineering-grade accuracy. Use Atkinson product Nyström, Gauss-Jacobi (with weight matching the singularity power), or graded-mesh Galerkin.
