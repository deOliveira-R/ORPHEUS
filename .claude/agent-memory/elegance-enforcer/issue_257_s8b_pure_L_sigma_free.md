# #257 S8b — pure-L σ-free StreamingOperator (drop the (L+C)−C fold)

PASS-WITH-NITS (`feature/field-typed-operator-algebra`, baseline `9316321`, UNCOMMITTED,
behavioral-NEUTRAL on the production composite; 61 S8b tests + 141 broad composite/matvec/

**What changed.** `StreamingOperator.apply` USED to compute full loss `loss_action(σ_t,ψ)`
then SUBTRACT `C=σ_t⊙ψ` to present pure L (the `(L+C)−C` fold). S8b makes it compute pure
streaming directly, σ-free, via a NEW named primitive `LossRepresentation.streaming_action(psi)`
(+`_transpose`) = `loss_action(self._zero_sigma_for(psi), psi)`. The `sigma_t` FIELD is DELETED
from `StreamingOperator` (dataclass); ~106 ctor sites migrated to `StreamingOperator(sn_mesh)`;
3 solver.py sites updated (incl. the `_rebind_sigma_t` path → rebuild composite so σ flows into
C only). `apply`/`apply_transpose` bodies collapse to one-line forwards.

## ⭐ LOAD-BEARING RULINGS (verified, durable)

**1. "Name the σ-free primitive but route through `loss_action(0)` rather than refactor
`loss_action = streaming + σ·ψ`" IS the principled call — do NOT demand the deeper refactor.**
The discriminator: refactoring `loss_action` itself re-baselines the `(L+C)` COMPOSITE matvec
(= `InvertibleOperator.apply`, what production SOLVE consumes) — FP re-association onto the HOT,
byte-pinned path for ZERO architectural gain. The chosen factoring keeps the streaming
discretization living ONCE in `loss_action` (no twin σ-free walk, Pattern 2) AND exposes the
σ-free leaf as a named domain primitive (Pattern 3). VERIFIED numerically:
`streaming_action(ψ) == loss_action(σ,ψ) − σ·ψ` to 16-52 ULP across σ∈{0.5,3,50} (affine
relation real, not asserted); `streaming_action` byte-repeatable (reads no σ);
`(L+C).apply == loss_action(σ)` BYTE-EXACT (composite untouched). STANDING TELL: when a carve
moves a term out of an operator leaf, the elegant boundary is "byte-identical COMPOSITE + ≤few-ULP
drift on the zero-graph-caller LEAF", NOT "refactor the shared kernel to make the decomposition
explicit at the cost of re-baselining the hot path". The decomposition being "implicit in the
kernel" does NOT bite when (a) it's explicit in 3 docstrings/comments + a structural test and
(b) production consumes the byte-identical composite.

**2. Pattern-4 σ-removal is COMPLETE (field GONE, not ignored).** `sigma_t` deleted from the
dataclass → `StreamingOperator(sn_mesh)` is the only constructible form → "pure L carrying a σ
it never reads" is UNSPELLABLE (anti-pattern #5 "an ignored σ is a lie" satisfied structurally).
`apply` reads `return self.loss_representation.streaming_action(psi)` = `L·ψ = Ω·∇ψ` (master
standard). Migration grep-clean: ZERO `StreamingOperator(...)` sites still pass a sigma arg
(the `reduced_operator.py` hits are a DIFFERENT class `ReducedStreamingOperator` — don't
false-positive on it).

**3. The re-baselining is STRUCTURALLY GROUNDED, not self-referential (textbook).**
`test_apply_equals_loss_action_minus_independent_collision_het` → renamed+strengthened to
`test_pure_L_plus_C_recovers_loss_action_het`: pins (1) `(L+C).apply == loss_action(σ)`
byte-EXACT (composite = structural ground) AND (2) `L.apply ≈ loss_action(σ) − C·ψ` to FP ULP
against a SEPARATELY-built `CollisionOperator` (subtrahend independently verified `σ·ψ`, not a
self-reference). Pure-L pinned to `(L+C)−C`, NOT to "whatever pure-L emits". New
`test_pure_L_sigma_free.py` C1 gate: tests the DEFINING property (σ-freedom) DIRECTLY on the
zero-graph-caller leaf (Mode-11 — `L.apply` called directly, solve routes around it) + a

independently-constructed structural reference + add a mutation test with teeth.
