A **concept** is a mathematical object of the code (an inverse, a quadrature, a solution), stated once by a row of
``docs/architecture/concept_table.toml``: its name, its definition, its kind, its place on the order structure (its
phase), the package that owns it (its layer), the ruling that admitted it and the wave that removes the debt against
it. A **role** says how a class stands to its concept; a **kind** says what sort of object the class is; the phase
orders the concepts so that a class may refer only to a class of an earlier or equal phase. The enumerations are
printed below from the tuples of the code that checks them, so this prose names none of them.

Every class of ``orpheus/`` outside ``derivations/`` declares its concept, its role and its kind in one comment on the
physical line that ends its class header, in the grammar printed below. The class that defines a concept is the one
that declares that role for it; which class that is, and whether the concept has a class at all, is derived by the
reader and never stored. A concept with no class yet carries the wave that creates it and lists the classes, if any,
that already realise it.

The **pending entries** are the exceptions the gates pin by equality, in ``docs/architecture/concept_debt.toml``. A
list never grows without a ruling, since every change of one is a visible edit of a tracked file, and an entry takes the
wave of its concept.

The checks are in ``tools/concept_table/checks.py`` and their gates in ``tests/gates/test_concept_table.py``. This page
is generated by ``python -m tools.concept_table.page`` from the table, the pending entries and the tree, and the gate
``tests/gates/test_concept_table_page.py`` asserts that it is what the generator writes.
