The concept table
=================

The declaration
---------------

The comment on the line that ends a class header, in exactly this field order:

.. code-block:: text

   # concept: <id> | role: <role> | kind: <kind>[.<subkind>] [| welded: <id>, <id>, ...]

Two examples, as the code renders them:

.. code-block:: text

   # concept: measure | role: head | kind: measure
   # concept: a | role: weld | kind: element.member | welded: a, b

The roles
~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 12 56 32

   * - role
     - meaning
     - tested by
   * - ``head``
     - the one class that defines the concept
     - G2, the head check
   * - ``arm``
     - a class of the head's lineage, a leaf of its closed sum, or one listed as its arm
     - G3, the arm test
   * - ``weld``
     - a class that defines two concepts at once, named in its welded list
     - the weld list and the unweld rule
   * - ``part``
     - a class only the concept's own classes read
     - G3, the part test
   * - ``component``
     - a class that a head, arm, weld or twin of the concept refers to
     - G3, the component test
   * - ``interface``
     - a Protocol through which the concept is used
     - G3, the interface test
   * - ``twin``
     - a deliberate second realisation outside the head's lineage, never merged with it
     - G3, the twin test
   * - ``annex``
     - a record kept beside the concept that is not part of it
     - G4, kind law 2
